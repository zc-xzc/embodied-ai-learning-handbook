### 1.2 统一分类框架

参考《A Survey on Large Language Model-based Autonomous Agents》（中国人民大学，2023）提出的统一框架，LLM Agent 的核心架构可归纳为四大模块：

```
┌─────────────────────────────────────────────────┐
│              LLM Agent 统一架构                   │
├─────────────────────────────────────────────────┤
│  Profiling Module（角色设定）                     │
│  → 确定 Agent 身份、角色、性格                     │
├─────────────────────────────────────────────────┤
│  Memory Module（记忆模块）                        │
│  → 短期/长期记忆、经验存储与检索                   │
├─────────────────────────────────────────────────┤
│  Planning Module（规划模块）                      │
│  → 任务分解、推理、反思、世界模型                   │
├─────────────────────────────────────────────────┤
│  Action Module（行动模块）                        │
│  → 工具使用、具身交互、多 Agent 通信                │
```

## 三、与具身智能直接相关的 Agent 论文精析

### 3.1 Voyager：LLM 驱动的开放式具身终身学习 Agent

> **论文**：Voyager: An Open-Ended Embodied Agent with Large Language Models
> **作者**：Guanzhi Wang 等（NVIDIA、Caltech、UTAustin）
> **发表**：NeurIPS 2023
> **环境**：Minecraft

**核心创新：**

Voyager 是首个由 LLM 驱动的具身终身学习 Agent，能够在 Minecraft 中持续探索世界、获取多样化技能、做出新发现，全程无需人工干预。其三大核心组件构成了一个完整的具身学习闭环：

```
┌──────────────────────────────────────────────────────────┐
│                    Voyager 架构                            │
│                                                            │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐    │
│  │ 自动课程      │→│ 迭代提示机制  │→│  技能库      │    │
│  │ Automatic    │  │ Iterative    │  │ Skill        │    │
│  │ Curriculum   │  │ Prompting   │  │ Library      │    │
│  │              │  │              │  │              │    │
│  │ 基于探索进度  │  │ 环境反馈      │  │ 代码即动作    │    │
│  │ 提出合适任务  │  │ 执行错误      │  │ 向量检索复用  │    │
│  │              │  │ 自我验证      │  │ 组合式增长    │    │
│  └──────────────┘  └──────────────┘  └──────────────┘    │
│          ↑                                    │           │
│          └──────────────循环────────────────────┘         │
└──────────────────────────────────────────────────────────┘
```

1. **自动课程（Automatic Curriculum）**：GPT-4 基于探索进度和 Agent 当前状态（如库存物品、生物群落、生命值等），以"发现尽可能多的新事物"为总目标，自下而上地生成合适难度的任务。这是新颖性搜索（Novelty Search）的上下文形式。

2. **技能库（Skill Library）**：每次成功完成的技能以可执行代码形式存储，并用 GPT-3.5 生成的描述嵌入作为检索键。复杂技能可通过组合简单程序合成，实现能力的快速复合增长，同时缓解灾难性遗忘。

3. **迭代提示机制（Iterative Prompting）**：GPT-4 生成可执行代码作为动作空间（而非低层运动指令），通过环境反馈（库存列表、附近实体）和执行错误进行多轮代码精炼，直到自我验证模块确认任务完成。

**关键设计选择——代码即动作（Code as Action）：**
Voyager 选择用程序代码而非低层运动指令作为动作空间，这是因为程序能自然表示时间扩展的和组合性的动作，对于 Minecraft 中的长时序任务至关重要。这一设计思路对真实机器人 VLA 模型具有重要启示：**高层技能的符号化表示比连续控制更适合 LLM 推理**。

**实验结果：**
- 获得 3.3 倍更多独特物品
- 行进距离 2.3 倍更长
- 解锁关键技术树里程碑速度快 15.3 倍
- 在新世界中可利用已有技能库从零解决新任务

**对具身智能的启示：**
- 终身学习是开放世界具身 Agent 的核心需求
- 技能的符号化（代码）表示便于组合与迁移
- LLM 的世界知识可有效引导探索，减少 RL 的样本复杂度
- 自我验证机制可替代外部奖励信号

### 3.2 LEO：3D 世界中的具身通用 Agent

> **论文**：An Embodied Generalist Agent in 3D World
> **作者**：Jiangyong Huang 等（北京通用人工智能研究院 BIGAI）
> **发表**：2023 预印本
> **环境**：3D 场景（ScanNet、3RScan、CLIPort 等）

**核心创新：**

LEO（Embodied Generalist Agent）是首个能在 3D 世界中感知、接地、推理、规划并行动的通用 Agent。它将所有任务统一为自回归序列预测问题，采用共享的 LLM 架构、目标和权重。

**两阶段训练范式：**

```
阶段一：3D Vision-Language Alignment（3D 视觉-语言对齐）
  输入：物体级 3D 点云 + 场景级多模态数据
  目标：建立 3D 场景表征与语言的对齐
  数据：660K 物体描述 + 354K 物体指代 + 20K 场景描述

阶段二：3D Vision-Language-Action Instruction Tuning（3D VLA 指令微调）
  输入：2D 自我中心图像 + 3D 点云 + 文本指令
  目标：输出文本响应和具身动作指令
  技术：LoRA 微调 Vicuna-7B，动作 token 映射到保留词表
```

**模型架构关键点：**

1. **多模态 Token 化**：文本用 SentencePiece（32K 子词）；2D 图像用 OpenCLIP ConvNext 编码；3D 点云用 PointNet++ + Spatial Transformer 生成物体中心 Token；连续动作离散化后映射到 LLM 的保留词表。

2. **统一序列格式**：
   ```
   [系统消息] [2D图像Token] [3D物体Token] [用户指令] [助手响应/动作Token]
   ```

3. **Object-centric Chain-of-Thought（O-CoT）**：提出基于场景图的提示与精炼方法，减少 LLM 生成数据的幻觉，提升数据质量。

**任务覆盖与实验：**
- 3D 描述（物体级/场景级）
- 3D 问答
- 具身推理（Situated QA）
- 具身导航
- 机器人操作（CLIPort 桌面场景）
- 任务规划与对话

**关键发现：**
- 3D 视觉-语言对齐预训练显著提升后续 VLA 指令微调性能
- 遵循 Scaling Law：增大训练数据持续提升通用 Agent 性能
- 统一模型在多任务上优于大多数任务专用模型

**对 VLA 模型的核心启示：**
LEO 的两阶段训练范式（先对齐再指令微调）直接映射到现代 VLA 模型训练：**先建立视觉-语言对齐（如 CLIP 式预训练），再进行动作指令微调**。这已成为 RT-2、OpenVLA 等 VLA 模型的标准范式。

### 3.3 DECKARD：LLM 引导的世界模型用于具身决策

> **论文**：Do Embodied Agents Dream of Pixelated Sheep? Embodied Decision Making using Language Guided World Modelling
> **作者**：Kolby Nottingham 等（UC Irvine、Allen AI）
> **发表**：ICML 2023
> **环境**：Minecraft

**核心创新：**

DECKARD（DECision-making for Knowledgable Autonomous Reinforcement-learning Dreamers）提出用 LLM 假设一个抽象世界模型（Abstract World Model, AWM），再通过环境经验验证和修正该模型，从而大幅提升 RL Agent 的样本效率。

**Dream-Wake 双阶段机制：**

```
┌─────────────────────────────────────────────────────┐
│              DECKARD 双阶段循环                       │
│                                                       │
│  ┌─────────────────┐       ┌─────────────────┐       │
│  │  Dream 阶段      │       │  Wake 阶段       │       │
│  │  （梦境）        │  →→→  │  （清醒）        │       │
│  │                  │       │                  │       │
│  │  LLM 假设 AWM    │       │  学习模块化策略   │       │
│  │  分解任务为      │       │  验证/修正 AWM    │       │
│  │  子目标 DAG      │       │  环境交互经验     │       │
│  │  建议探索节点    │       │  标记已验证节点   │       │
│  └─────────────────┘       └─────────────────┘       │
│            ↑                        │                 │
│            └─────── 循环 ────────────┘                │
└─────────────────────────────────────────────────────┘
```

1. **Dream 阶段**：LLM 通过少样本提示，将任务分解为子目标的有向无环图（DAG），形成假设的 AWM。基于此 DAG 建议下一个探索节点，忽略与当前任务无关的节点。

2. **Wake 阶段**：Agent 学习每个子目标的模块化策略（基于 POMDP），并在环境中执行。若成功完成子目标，将其标记为"已验证"；若失败，修正 AWM 中的依赖关系。

**核心洞察：**
- LLM 的知识是"有噪声的"互联网规模信息，不应直接用于执行时决策
- 正确做法：将 LLM 作为**探索阶段的先验知识源**，通过环境交互验证和修正
- 这种"假设-验证"范式能有效融合 LLM 的世界知识与环境的真实动力学

**实验结果：**
- 样本效率比无 LLM 引导的版本快一个数量级（12 倍）
- 对 LLM 任务分解错误具有鲁棒性
- 成功融合了 LLM 噪声知识与环境接地经验

**对具身智能的启示：**
DECKARD 展示了 LLM 与 RL 的深层融合方式——**LLM 不替代 RL，而是为 RL 提供结构化的探索先验**。这对真实机器人学习意义重大：在奖励稀疏的长期操作任务中，LLM 可以提供子目标分解，大幅缩小搜索空间。

### 3.4 Steve-Eye：为 LLM 具身 Agent 装备视觉感知

> **论文**：Steve-Eye: Equipping LLM-based Embodied Agents with Visual Perception in Open Worlds
> **作者**：Sipeng Zheng 等（北京智源 AI 研究院、北京大学）
> **发表**：2023 预印本
> **环境**：Minecraft

**核心创新：**

Steve-Eye 指出此前的 LLM 具身 Agent（如 Voyager、GITM）将整个世界转化为文本，相当于"蒙眼玩文字游戏"，忽略了开放世界的视觉丰富性。Steve-Eye 是一个端到端训练的大型多模态模型，将 LLM 与视觉编码器集成，处理视觉-文本输入并生成多模态反馈。

**三大核心功能：**

| 功能 | 说明 | 对应能力 |
|------|------|---------|
| 多模态感知 | 处理视觉输入，描述 Agent 状态和环境特征 | 环境理解 |
| 基础知识库 | 掌握决策所需的基础知识（如合成配方） | 常识推理 |
| 技能预测与规划 | 生成可执行的技能计划和动作序列 | 行动决策 |

**数据与训练：**

1. **数据集**：构建了 850K 开放世界指令对，采用半自动化策略收集，包含逐步状态、环境特征和行动所需知识。

2. **两阶段训练**（类似 LLaVA）：
   - 阶段一：视觉编码器与 LLM 的多模态元素对齐
   - 阶段二：用构建的指令数据集进行指令微调

**评估基准：**
- ENV-VC（环境视觉描述）：评估感知和描述能力
- FK-QA（基础知识问答）：评估决策所需知识掌握
- SPP（技能预测与规划）：评估行动和规划能力

**对具身智能的启示：**
Steve-Eye 的核心贡献在于证明了**视觉感知对具身 Agent 的必要性**。纯文本输入的 Agent 无法处理需要视觉理解的任务（如识别物体外观、判断空间关系）。这直接指向了现代 VLA 模型的核心设计——**视觉编码器与语言模型的深度融合是具身智能的基础**。

---

### 3.5 Co-LLM-Agents：用 LLM 模块化构建协作具身 Agent

> **论文**：Building Cooperative Embodied Agents Modularly with Large Language Models
> **作者**：Hongxin Zhang 等（UMass、清华、MIT）
> **发表**：ICLR 2024
> **环境**：C-WAH（Communicative Watch-And-Help）、TDW-MAT（ThreeDWorld Multi-Agent Transport）

**核心创新：**

这是首个系统性研究 LLM 在具身多 Agent 协作中规划和通信能力的工作。框架使具身 Agent 能够与其他 Agent 或人类协作完成长时序任务，无需微调或少样本提示。

**五模块架构：**

```
┌─────────────────────────────────────────────────────┐
│            Co-LLM-Agents 五模块框架                    │
│                                                       │
│  ┌──────────┐   ┌──────────┐   ┌──────────────┐     │
│  │ 观察      │→│ 信念      │→│ 通信          │     │
│  │ Module   │   │ Module   │   │ Module       │     │
│  │          │   │          │   │ (LLM驱动)    │     │
│  │ 场景图    │   │ 任务进度  │   │ 决定何时      │     │
│  │ 物体关系  │   │ 自我状态  │   │ 说什么        │     │
│  │ 其他Agent │   │ 他人状态  │   │              │     │
│  │ 位置     │   │ 场景记忆  │   │              │     │
│  └──────────┘   └──────────┘   └──────┬───────┘     │
│                         ↓              │             │
│                  ┌──────────────┐      │             │
│                  │ 推理          │←─────┘             │
│                  │ Module       │                    │
│                  │ (LLM驱动)    │                    │
│                  │ 综合信息      │                    │
│                  │ 决定高层计划  │                    │
│                  └──────┬───────┘                    │
│                         ↓                           │
│                  ┌──────────────┐                    │
│                  │ 规划          │                    │
│                  │ Module       │                    │
│                  │ 生成原始动作  │                    │
│                  └──────────────┘                    │
└─────────────────────────────────────────────────────┘
```

1. **观察模块**：处理原始观察（符号或自我中心视觉），提取场景图、物体关系、地图信息等。

2. **信念模块**：跟踪四类信息——任务进度、自我状态、他人状态、场景记忆。解决 LLM 无内在记忆的问题，处理记忆与观察冲突。

3. **通信模块（LLM 驱动）**：解决"说什么"和"何时说"两个问题，利用 LLM 的自由对话生成能力。

4. **推理模块（LLM 驱动）**：综合所有模块信息，决定高层计划，包括何时通信。

5. **规划模块**：将高层计划转化为原始动作。

**关键发现：**
- GPT-4 超越强规划基线方法，无需微调或少样本提示
- LLM Agent 用自然语言通信能获得人类更多信任
- 用户研究证实 LLM 实现了有效且值得信赖的人机协作

**对具身智能的启示：**
多 Agent 协作是具身智能走向实用的关键能力。Co-LLM-Agents 的五模块框架可直接迁移到**多机器人协作**场景：信念模块对应机器人的状态估计，通信模块对应多机器人通信协议，推理与规划模块对应协作决策。自然语言通信的优势——可解释性和人类信任度——在人机协作场景中尤为重要。

### 3.6 Zero-Shot Planner：语言模型作为零样本规划器

> **论文**：Language Models as Zero-Shot Planners: Extracting Actionable Knowledge for Embodied Agents
> **作者**：Wenlong Huang、Pieter Abbeel、Deepak Pathak、Igor Mordatch
> **发表**：ICML 2023（预印本 2022）
> **环境**：VirtualHome

**核心创新：**

这是 LLM 用于具身任务规划的奠基性工作。核心发现是：**足够大的预训练 LLM，在适当提示下，无需任何额外训练即可将高层任务（如"做早餐"）分解为可执行的动作步骤（如"打开冰箱"）**。

**关键发现与挑战：**

1. **惊喜发现**：GPT-3（175B）和 Codex（12B）在单样本提示下能生成语义合理的动作计划，且该效果仅在大模型中出现（小模型如 GPT-2 1.5B 无法做到）。

2. **可执行性问题**：LLM 生成的计划虽然语义正确，但常无法精确映射到环境可接受的动作（Admissible Actions）。

3. **解决方案三步法**：
   ```
   步骤1：查询 LLM 生成动作计划（零样本）
   步骤2：语义翻译——用 RoBERTa 将输出映射到最相似的可接受动作
   步骤3：自回归修正——将已翻译的动作作为条件，引导后续生成
   ```

4. **动态示例选择**：提供与查询任务相似的已知示例作为弱监督，改善知识提取。

**结果：** 可执行性从 18% 提升至 79%，但语义正确性有所下降——揭示了可执行性与正确性之间的权衡。

**对具身智能的启示：**
这项工作首次系统验证了 LLM 的世界知识可直接用于具身规划，奠定了后续 SayCan、Code as Policies、Voyager 等工作的基础。其核心启示是：**LLM 的规划能力来自预训练积累的世界知识，而非任务特定训练**，但需要接地（Grounding）机制来确保可执行性。

### 4.2 第一阶段：基础理论奠基（2017-2020）

#### 4.2.1 Deep Reinforcement Learning from Human Preferences（2017）

> **作者**：Paul F. Christiano、Jan Leike、Tom B. Brown 等（OpenAI、DeepMind）

**历史地位**：RLHF 的开山之作，首次将人类偏好学习扩展到深度 RL。

**核心方法：**

1. **轨迹对比范式**：不要求人类给出绝对数值评分，而是让人类比较两段短视频片段，选择更优者。这种方式对人类更友好且同样有效。

2. **双系统并行训练**：
   ```
   人类偏好 → 训练奖励预测器（Reward Predictor）
   奖励预测器 → 指导 RL 算法优化策略
   两个过程异步并行
   ```

3. **高效反馈**：仅需不到 Agent 与环境交互的 1% 的人类反馈，即可有效学习。约 15 分钟到 5 小时的人类时间足以学习复杂行为。

**实验域**：Atari 游戏（ALE）、MuJoCo 机器人运动（后空翻、交通流跟随等）。

**核心贡献**：
- 证明了从人类偏好学习复杂行为的可行性
- 建立了"偏好数据→奖励模型→RL 优化"的标准范式
- 将人类反馈成本降低到可实用化水平

**对具身智能的奠基意义**：论文明确提到"用 RL 训练机器人清理桌子或炒鸡蛋"的愿景——这正是今天具身智能的核心场景。其从人类偏好学习奖励函数的范式，为后续机器人学习的偏好优化奠定了基础。

#### 4.2.2 Learning to Summarize from Human Feedback（NeurIPS 2020）

> **作者**：Nisan Stiennon、Long Ouyang 等（OpenAI）

**历史地位**：将 RLHF 从 RL 环境迁移到语言模型领域的关键里程碑。

**核心方法：**

1. **数据集**：Reddit TL;DR 数据集，收集 64,832 条摘要比较。

2. **三步流程**：
   ```
   步骤1：监督微调（SFT）—— 在 TL;DR 上微调 GPT-3
   步骤2：训练奖励模型（RM）—— 从人类偏好对比中学习
   步骤3：PPO 优化 —— 最大化 RM 给出的奖励
   ```

3. **关键发现**：
   - 人类反馈模型显著优于更大的仅监督学习模型
   - 奖励模型泛化到新数据集（CNN/DM）无需领域特定微调
   - 优化 RM 比优化 ROUGE 效果更好（验证了 RM 比自动指标更接近真实质量）

**核心贡献**：建立了语言模型 RLHF 的标准范式（SFT→RM→PPO），直接被 InstructGPT 继承。

---

### 4.3 第二阶段：工程化对齐（2022）

#### 4.3.1 InstructGPT：三步 RLHF 对齐范式

> **论文**：Training Language Models to Follow Instructions with Human Feedback
> **作者**：Long Ouyang 等（OpenAI）
> **发表**：2022

**核心问题**：更大的语言模型并不会自动变得更好地遵循用户意图——它们可能生成不真实、有毒或无用的输出。即"语言模型目标与用户意图不对齐"。

**三步对齐流程：**

```
┌─────────────────────────────────────────────────────────────┐
│                  InstructGPT 三步 RLHF 流程                   │
│                                                               │
│  步骤1：SFT（监督微调）                                       │
│  ┌──────────┐    人类示范    ┌──────────┐                    │
│  │  GPT-3   │  ──────────→  │  SFT模型  │                    │
│  │ (预训练)  │   13K指令     │          │                    │
│  └──────────┘               └────┬─────┘                    │
│                                   │                           │
│  步骤2：RM（奖励模型训练）          ↓                           │
│  ┌──────────┐   人类偏好    ┌──────────┐                    │
│  │  SFT模型  │ ──────────→  │ 奖励模型  │                    │
│  │  采样输出  │  33K对比     │  (RM)    │                    │
│  └──────────┘  (A/B/C/D)   └────┬─────┘                    │
│                                   │                           │
│  步骤3：PPO（强化学习优化）         ↓                           │
│  ┌──────────┐   RM奖励      ┌──────────┐                    │
│  │  SFT模型  │ ──────────→  │PPO-ptx   │                    │
│  │          │  最大化奖励    │(InstructGPT)│                  │
│  └──────────┘  +预训练混合   └──────────┘                    │
│                                                               │
│  关键：PPO-ptx 混合预训练分布更新，缓解"对齐税"               │
└─────────────────────────────────────────────────────────────┘
```

**三步详解：**

1. **步骤1 - SFT（Supervised Fine-Tuning）**：
   - 雇佣 40 名标注员，基于筛选测试确保质量
   - 收集约 13K 条人类示范数据（标注员编写期望输出）
   - 在 GPT-3 上进行监督微调

2. **步骤2 - RM（Reward Model 训练）**：
   - 对同一提示生成多个输出（A/B/C/D）
   - 人类标注员对输出进行排名
   - 训练 RM 预测人类偏好（输入提示+输出，输出标量奖励）

3. **步骤3 - PPO（Proximal Policy Optimization）**：
   - 用 RM 作为奖励函数
   - PPO 算法最大化奖励
   - **PPO-ptx 创新**：混合预训练分布的更新，缓解在公共 NLP 数据集上的性能退化（"对齐税"）

**核心结果：**

| 指标 | 结果 |
|------|------|
| 参数效率 | 1.3B InstructGPT 优于 175B GPT-3（100 倍参数差距） |
| 偏好率 | 175B InstructGPT 优于 175B GPT-3 达 85% |
| 真实性 | TruthfulQA 上 truthful+informative 比例翻倍 |
| 幻觉率 | 封闭域任务从 41% 降至 21% |
| 毒性 | 礼貌提示下减少约 25% |
| 泛化性 | 能跟随训练分布外的指令（代码摘要、多语言） |

**对齐三原则（HHH）：**
- **Helpful（有用）**：帮助用户解决任务
- **Honest（诚实）**：不编造信息、不误导
- **Harmless（无害）**：不对人或环境造成伤害

**对 VLA 模型的启示：**
InstructGPT 的三步范式是所有后续对齐工作的模板。对于 VLA 模型，这意味着：**先 SFT（模仿学习/指令微调），再用人类偏好训练奖励模型，最后用 RL 优化策略**。这正是 RLHF 应用于机器人策略优化的直接路径。

### 4.4 第三阶段：可扩展监督与 AI 反馈（2022 末至今）

#### 4.4.1 Constitutional AI：从 RLHF 到 RLAIF

> **论文**：Constitutional AI: Harmlessness from AI Feedback
> **作者**：Yuntao Bai 等（Anthropic）
> **发表**：2022

**核心动机**：随着 AI 能力增长，人类难以监督所有方面；RLHF 需要数万人类偏好标签，成本高昂且迭代慢。

**核心创新——用 AI 替代人类反馈（RLAIF）：**

```
┌──────────────────────────────────────────────────────────┐
│              Constitutional AI (CAI) 流程                  │
│                                                            │
│  ┌─────────────── 监督阶段（SL-CAI）──────────────┐       │
│  │                                                  │       │
│  │  初始模型 → 采样响应 → AI 自我批评 → AI 修订    │       │
│  │                        (基于宪法原则)             │       │
│  │                                                  │       │
│  │  修订响应 → 微调原始模型 → SL-CAI 模型           │       │
│  └──────────────────────────────────────────────────┘       │
│                          ↓                                  │
│  ┌─────────────── RL 阶段（RL-CAI）───────────────┐       │
│  │                                                  │       │
│  │  SL-CAI 模型 → 采样响应对 → AI 评估偏好         │       │
│  │                                                  │       │
│  │  AI 偏好数据 → 训练偏好模型(PM) → RL 优化        │       │
│  │                                                  │       │
│  │  最终模型: RL-CAI (无害且非回避)                 │       │
│  └──────────────────────────────────────────────────┘       │
│                                                            │
│  宪法原则：~10 条自然语言原则，如"不帮助危险行为"等        │
└──────────────────────────────────────────────────────────┘
```

**两阶段详解：**

1. **监督阶段（SL-CAI）**：
   - 从初始模型采样响应
   - AI 根据"宪法"原则自我批评（Critique）
   - AI 修订响应（Revision）
   - 在修订响应上微调模型

2. **RL 阶段（RL-CAI）**：
   - 从微调模型采样响应对
   - AI 模型评估哪个更好（AI Feedback）
   - 从 AI 偏好训练偏好模型（PM）
   - 用 PM 作为奖励信号进行 RL 训练

**关键突破：**
- **无需人类有害性标签**：唯一人类监督是~10 条自然语言原则
- **非回避性（Non-evasive）**：不像传统 RLHF 那样回避有害查询，而是解释其反对理由
- **帕累托改进**：在给定有用性水平下更无害
- **思维链（CoT）推理**：提升决策透明度和性能

**与 InstructGPT 的对比：**

| 维度 | InstructGPT (RLHF) | Constitutional AI (RLAIF) |
|------|:---:|:---:|
| 反馈来源 | 人类标注员 | AI 模型 |
| 人类参与 | 数万偏好标签 | ~10 条原则 |
| 有害性标签 | 需要人类标注 | 无需人类标注 |
| 迭代成本 | 高（需重新收集数据） | 低（修改原则即可） |
| 透明度 | 中 | 高（原则可审查） |
| 回避性 | 较高 | 低（解释式拒绝） |

## 五、对 VLA 模型训练的启示

### 5.1 RLHF 如何应用于机器人策略优化

RLHF 技术演进对 VLA（Vision-Language-Action）模型训练的启示可分为三个层次：

#### 5.1.1 直接迁移：三步范式映射

InstructGPT 的三步 RLHF 范式可直接映射到 VLA 模型训练：

```
┌─────────────────────────────────────────────────────────────┐
│           VLA 模型的 RLHF 训练范式                          │
│                                                               │
│  步骤1：SFT（模仿学习/指令微调）                              │
│  ┌──────────────┐    遥操作数据    ┌──────────────┐         │
│  │ 预训练VLM    │  ──────────→    │  VLA-SFT     │         │
│  │ (如PaLI/LLaVA)│  人类示范轨迹   │              │         │
│  └──────────────┘               └──────┬───────┘         │
│                                         │                   │
│  步骤2：RM（奖励模型训练）               ↓                   │
│  ┌──────────────┐  人类偏好     ┌──────────────┐         │
│  │  VLA-SFT     │ ──────────→  │ 奖励模型(RM)  │         │
│  │  采样轨迹     │  轨迹对比     │              │         │
│  └──────────────┘             └──────┬───────┘         │
│                                         │                   │
│  步骤3：RL优化                           ↓                   │
│  ┌──────────────┐   RM奖励      ┌──────────────┐         │
│  │  VLA-SFT     │ ──────────→  │  VLA-RLHF    │         │
│  │              │  PPO优化      │  (最终模型)   │         │
│  └──────────────┘             └──────────────┘         │
└─────────────────────────────────────────────────────────────┘
```

**关键对应关系：**

| InstructGPT | VLA 模型 | 说明 |
|------------|---------|------|
| 文本提示 | 语言指令+视觉观察 | 任务指定方式 |
| 文本输出 | 动作 Token | 输出空间 |
| 人类示范文本 | 遥操作轨迹 | SFT 数据 |
| 文本偏好对比 | 轨迹偏好对比 | RM 训练数据 |
| PPO 优化文本 | PPO 优化动作策略 | RL 阶段 |
| PPO-ptx 预训练混合 | VLM 预训练混合 | 缓解对齐税 |

#### 5.1.2 深层启示：从具身 Agent 论文中提炼

**启示1：LLM 作为探索先验（来自 DECKARD）**

DECKARD 的 Dream-Wake 范式提示了一种混合训练策略：
- **Dream 阶段**：用 LLM 分解长时序操作任务为子目标序列
- **Wake 阶段**：对每个子目标学习模块化策略，验证和修正 LLM 的分解
- **应用**：在奖励稀疏的机器人操作任务中，LLM 提供子目标作为内在奖励，大幅降低样本复杂度

**启示2：技能库与组合式增长（来自 Voyager）**

Voyager 的技能库机制对 VLA 训练的启示：
- 将已学会的技能以可复用形式存储（代码/参数化策略）
- 新任务通过检索和组合已有技能解决
- 技能的符号化表示便于跨任务迁移
- **应用**：VLA 模型可采用"技能库 + 检索增强"架构，而非每次从零学习

**启示3：两阶段训练范式（来自 LEO）**

LEO 的"先对齐再指令微调"范式已成为 VLA 标准：
- **阶段一**：视觉-语言对齐（建立感知基础）
- **阶段二**：VLA 指令微调（注入动作能力）
- LoRA 等参数高效微调降低计算成本
- **应用**：RT-2、OpenVLA 等均采用此范式

**启示4：视觉感知的必要性（来自 Steve-Eye）**

Steve-Eye 证明纯文本 Agent 的局限性：
- VLA 模型必须有强大的视觉编码器
- 视觉-语言深度融合（而非简单拼接）是关键
- 多模态指令数据的质量决定上限

**启示5：多体协作框架（来自 Co-LLM-Agents）**

五模块架构可迁移到多机器人系统：
- 信念模块 → 多机器人状态估计
- 通信模块 → 机器人间通信协议
- 推理模块 → 协作决策
- 自然语言通信提升人机协作可信度

### 5.2 RLHF 在机器人学习中的具体应用路径

#### 5.2.1 偏好学习用于机器人操作

基于 Christiano et al. (2017) 的轨迹对比范式：

```
训练流程：
1. 机器人执行任务，录制多段轨迹视频
2. 人类标注员比较轨迹对（"A比B更好"）
3. 训练奖励模型预测人类偏好
4. 用 RL（如 PPO/SAC）优化机器人策略
5. 迭代收集偏好数据
```

**优势**：
- 无需设计精确奖励函数
- 人类直觉判断比工程化奖励更自然
- 可处理难以形式化的任务（如"优雅地倒水"）

**挑战**：
- 人类反馈成本（可参考 RLAIF 解决）
- 奖励模型的泛化性
- 分布外行为的评估

#### 5.2.2 从 RLHF 到 RLAIF：机器人反馈的可扩展化

Constitutional AI 的 RLAIF 思想可直接迁移：

| CAI 阶段 | 机器人学习对应 |
|----------|-------------|
| 宪法原则 | 机器人安全约束、操作规范 |
| AI 自我批评 | VLM 评估操作视频是否违反约束 |
| AI 偏好评估 | VLM 比较两条轨迹的优劣 |
| RLAIF 优化 | 用 AI 偏好训练奖励模型并 RL 优化 |

**核心价值**：用 VLM（如 GPT-4V）作为"AI 评估者"，替代人类标注员进行轨迹偏好评估，大幅降低反馈成本。这正是当前机器人学习的前沿方向。

#### 5.2.3 预训练阶段的偏好注入

参考《Pretraining Language Models with Human Preferences》，可在 VLA 预训练阶段就引入偏好信号：
- 在大规模机器人数据预训练时加入人类偏好约束
- 使模型从预训练开始就倾向于生成安全、有用的行为
- 减少后训练对齐的需求
