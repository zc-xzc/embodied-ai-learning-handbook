## 一、遥操作技术全景

### 1.1 遥操作的核心价值

遥操作是连接人类知识与机器人策略的桥梁：
- **数据桥梁**：为VLA模型提供高质量示教数据
- **能力延伸**：让机器人实时复现人的手部轨迹
- **跨体泛化**：GAE实现毫秒级同步，支持单人操控成百上千台异地机器人

### 1.2 控制范式分野

| 范式 | 代表方法 | 特点 |
|------|----------|------|
| MPC | 模型预测控制 | 基于物理模型，可解释性强 |
| RL/IL | 强化学习/模仿学习 | 数据驱动，泛化性强 |

## 二、UMI标准化采集方案

### 2.1 UMI（Universal Manipulation Interface）

斯坦福大学提出的标准化方案（arXiv:2402.10329）：

**核心创新**：
- "在野教学"（In-the-wild Teaching），仅需手持夹爪和GoPro相机
- 不依赖昂贵动捕系统
- 相机中心坐标系：相机安装在夹爪上实现100%标定免除
- 学习夹爪与目标物体的相对几何关系

### 2.2 ORB-SLAM3优化管道

```
视频流 → 特征点提取 → 相机姿态计算 → 行为轨迹生成
  → 延迟匹配(Latency Matching) → 消除动作抖动
```

### 2.3 扩散策略数据喂入

Zarr格式数据集 → 扩散模型 → 捕捉人类动作多峰性（Multimodality）→ 提升OOD对象成功率

## 四、数据采集工程实践

### 4.1 采集系统架构

```
VR设备/动捕 → 通信层(P2P/USB/Type-C) → 上位机(NUC)
  → 时间戳同步(NTP/PTP) → 数据存储(LeRobot v3)
```

### 4.2 12位精度控制

舵机控制信号定义：
- 矫正位：初始位置校准
- 速度位：中间为0，范围为-1到+1
- 位置位：0-4095步
- 加速度偏移位

线性映射逻辑：头锥角度范围按比例映射到舵机步数范围。

### 4.3 通信协议

| 接口 | 用途 | 特点 |
|------|------|------|
| GPIO | 舵机控制信号 | 直接，低延迟 |
| USB | 上位机通信 | 稳定，广泛兼容 |
| Type-C | 通信备用 | 与USB识别一致 |

## 五、动作重定向（Retargeting）

### 5.1 核心问题

将人类动作映射到机器人关节空间：
- yaw轴解耦：避免奇异点
- 毫米级正样/百毫米级负样过滤
- 关节角度调零校准

### 5.2 Retargeting质检

- 正样：毫米级精度
- 负样：百毫米级过滤
- 精灵系列遥操设备无缝部署G2

### 5.3 残差学习+自适应采样

底层控制策略：
```
高层VLA输出参考轨迹 → 残差学习修正 → 自适应采样 → 底层执行
```

## 六、Sim-to-Real数据共生

### 6.1 虚实数据配比策略

| 策略 | 真机数据 | 仿真数据 | 效果 |
|------|----------|----------|------|
| 纯真机SFT | 200条 | 0 | 基准 |
| 纯仿真SFT | 0 | 100条 | 低于真机 |
| ROQ混合 | 20条 | 1000条 | 超越200条真机 |
| Lidea策略 | 20% | 80% | 最优 |

### 6.2 Sim-to-Real Gap深度矛盾

**核心发现**：仿真越好真机反而越差

原因：
- 域随机化(DR)过大引起概率性异常
- 仿真过于逼真导致过拟合仿真分布
- 纹理/光照/背景差异无法完全消除

**解决方案**：
- 前训练/后训练分离
- 仿真-真机对齐设计：保证相同点（初始状态、任务定义），允许相似点（运动学），不要求一致点（纹理、光照）

### 6.3 全机载ONNX部署

- 推理频率：500Hz
- 延迟：<50ms
- 边缘设备：Jetson ORIN / NUC

## 八、延迟与同步

### 8.1 延迟物理极限

- 30fps视频：每帧约33ms
- 人手延迟感知：依赖环境而非动作类型
- 通信毫秒级延迟需克服

### 8.2 同步纪律

快照同步：
- 视觉与动作信号时间戳对齐
- NTP/PTP协议保证毫秒级同步
- MCAP格式记录多模态数据
