## 一、为什么需要 VLA+RL

### 1.1 纯模仿学习的局限

```
VLA 模型通过 SFT（监督微调）训练的局限：

1. 数据质量上限
   - 人类演示质量参差不齐
   - 演示数据量有限
   - 无法覆盖所有场景

2. 无法超越人类水平
   - SFT 只能模仿人类行为
   - 无法发现更优策略

3. 分布外泛化差
   - 遇到训练中未见的情况就失败
   - 无法自主适应新环境

4. 无法从环境反馈中改进
   - SFT 是开环训练
   - 无法根据实际执行结果优化
```

### 1.2 RL 如何补充 VLA

```python
"""
RL 补充 VLA 的方式

1. 在线微调
   VLA 预训练 → 在环境中用 RL 微调 → 更优策略

2. 探索新策略
   RL 可以发现 SFT 数据中不存在的策略

3. 自主改进
   通过环境反馈持续优化

4. 任务特定优化
   针对特定任务的奖励函数精细调整

挑战：
  - 样本效率（RL 需要大量交互）
  - 安全性（探索可能导致危险）
  - 奖励设计
  - 训练稳定性
"""
```

## 二、在线强化学习微调 VLA

### 2.1 微调框架

```python
import torch
import torch.nn as nn

class VLA_RL_Finetuner:
    """VLA + RL 微调框架"""
    def __init__(self, vla_model, reward_fn, lr=1e-5):
        self.vla = vla_model
        self.reward_fn = reward_fn
        self.optimizer = torch.optim.Adam(vla_model.parameters(), lr=lr)
        
        # 保留 SFT 模型的引用（用于 KL 约束）
        self.sft_model = None  # 冻结的 SFT 副本
    
    def collect_episode(self, env, max_steps=200):
        """收集一个 episode 的数据"""
        trajectory = []
        obs = env.reset()
        
        for step in range(max_steps):
            # VLA 预测动作
            with torch.no_grad():
                action = self.vla.predict_action(obs)
            
            # 执行
            next_obs, reward, done, info = env.step(action)
            
            trajectory.append({
                'obs': obs,
                'action': action,
                'reward': reward,
                'next_obs': next_obs,
                'done': done,
                'info': info,
            })
            
            obs = next_obs
            if done:
                break
        
        return trajectory
    
    def compute_returns(self, trajectory, gamma=0.99):
        """计算折扣回报"""
        returns = []
        G = 0
        for t in reversed(trajectory):
            G = t['reward'] + gamma * G
            returns.insert(0, G)
        return returns
    
    def ppo_update(self, trajectories, clip_eps=0.2, kl_weight=0.1):
        """PPO 风格的更新"""
        for trajectory in trajectories:
            returns = self.compute_returns(trajectory)
            
            for t, G in zip(trajectory, returns):
                obs = t['obs']
                action = t['action']
                
                # 当前策略
                new_action = self.vla.predict_action_with_logprob(obs)
                
                # 计算 log prob
                log_prob_new = self.vla.get_log_prob(obs, action)
                
                # SFT 模型的 log prob（KL 约束）
                if self.sft_model is not None:
                    with torch.no_grad():
                        log_prob_sft = self.sft_model.get_log_prob(obs, action)
                    kl_penalty = kl_weight * (log_prob_new - log_prob_sft)
                else:
                    kl_penalty = 0
                
                # PPO loss
                advantage = G  # 简化：直接用 return 作为 advantage
                ratio = torch.exp(log_prob_new - log_prob_new.detach())
                
                loss = -torch.min(
                    ratio * advantage,
                    torch.clamp(ratio, 1 - clip_eps, 1 + clip_eps) * advantage
                ) + kl_penalty
                
                self.optimizer.zero_grad()
                loss.backward()
                self.optimizer.step()
```

### 2.2 关键挑战

```python
"""
VLA + RL 在线微调的挑战

1. 样本效率
   - VLA 模型大（7B+），RL 需要大量交互
   - 真机交互成本高
   - 解决：仿真中 RL 微调 + Sim2Real

2. 训练稳定性
   - 大模型 + RL 容易崩溃
   - 解决：KL 约束（限制与 SFT 的偏离）
   
3. 奖励稀疏
   - 很多任务只有最终成功/失败
   - 解决：密集奖励 + 课程学习

4. 安全性
   - RL 探索可能导致危险行为
   - 解决：安全约束 + 人在环路

5. 计算成本
   - VLA 前向传播慢
   - 解决：量化 + LoRA + 动作缓存
"""
```

## 三、离线到在线 RL

### 3.1 Offline-to-Online 流程

```
离线到在线 RL (Offline-to-Online RL)

阶段1：离线训练
  用已有的演示数据训练 VLA
  方法：BC / 离线 RL (CQL, IQL)
  
阶段2：在线微调
  用训练好的 VLA 在环境中交互
  逐步用 RL 优化策略
  
阶段3：持续改进
  不断收集新数据，持续训练

优势：
  - 离线阶段建立基础能力
  - 在线阶段精细优化
  - 比纯在线 RL 样本效率高
```

### 3.2 离线 RL 方法

```python
"""
离线 RL 方法

1. CQL (Conservative Q-Learning)
   - 保守估计 Q 值，避免过估计
   - 对未见过的动作给低 Q 值

2. IQL (Implicit Q-Learning)
   - 用 expectile regression 估计 Q 值
   - 不需要查询未见动作

3. AWAC (Advantage Weighted Actor-Critic)
   - 用优势函数加权 BC
   - 高优势的动作权重大

4. RLHF 风格
   - 训练奖励模型
   - 用 PPO 优化
"""
```

## 四、奖励设计

### 4.1 奖励函数设计原则

```python
"""
VLA + RL 的奖励设计

1. 任务完成奖励（稀疏）
   success: +10.0
   failure: -1.0
   
2. 进度奖励（密集）
   - 到目标距离的减少量
   - 物体高度的增量
   
3. 效率奖励
   - 步数惩罚：-0.01 * step
   - 能耗惩罚：-0.001 * torque²
   
4. 安全惩罚
   - 碰撞：-5.0
   - 关节超限：-1.0
   - 摔倒：-10.0
   
5. 人类反馈奖励
   - 人类标注偏好
   - 训练奖励模型
"""

class VLA_Reward:
    """VLA RL 奖励函数"""
    def __init__(self):
        self.weights = {
            "success": 10.0,
            "failure": -1.0,
            "progress": 1.0,
            "step_penalty": -0.01,
            "collision": -5.0,
            "energy": -0.001,
        }
    
    def compute(self, obs, action, next_obs, info, target_pos=None):
        reward = 0
        
        # 任务完成
        if info.get("success", False):
            reward += self.weights["success"]
            return reward
        if info.get("failure", False):
            reward += self.weights["failure"]
        
        # 进度奖励
        if target_pos is not None:
            curr_dist = self._distance(next_obs, target_pos)
            prev_dist = self._distance(obs, target_pos)
            reward += self.weights["progress"] * (prev_dist - curr_dist)
        
        # 步数惩罚
        reward += self.weights["step_penalty"]
        
        # 碰撞
        if info.get("collision", False):
            reward += self.weights["collision"]
        
        # 能耗
        if "torque" in info:
            reward += self.weights["energy"] * np.sum(info["torque"]**2)
        
        return reward
    
    def _distance(self, obs, target):
        """计算距离"""
        # 简化
        return np.linalg.norm(obs[:3] - target)
```

## 五、安全约束

```python
"""
VLA + RL 的安全约束

1. 动作安全过滤
   - 在 RL 输出动作上施加安全约束
   - 限制关节速度、力矩等

2. 状态安全约束
   - 检测危险状态（接近碰撞）
   - 触发安全停止

3. 策略 KL 约束
   - 限制 RL 策略与 SFT 策略的偏离
   - 防止探索导致灾难性行为

4. 人在环路
   - 人类监控 RL 训练
   - 在危险时介入
"""

class SafeRLWrapper:
    """安全 RL 包装器"""
    def __init__(self, vla_model, sft_model, kl_threshold=0.5):
        self.vla = vla_model
        self.sft = sft_model
        self.kl_threshold = kl_threshold
    
    def safe_action(self, obs, rl_action):
        """安全过滤动作"""
        # 1. 动作限幅
        rl_action = np.clip(rl_action, -1.0, 1.0)
        
        # 2. 速度限制
        # rl_action = self._limit_velocity(rl_action, prev_action)
        
        # 3. KL 检查
        kl = self._compute_kl(obs, rl_action)
        if kl > self.kl_threshold:
            # 回退到 SFT 策略
            print(f"KL 过大 ({kl:.3f}), 回退到 SFT")
            return self.sft.predict_action(obs)
        
        return rl_action
    
    def _compute_kl(self, obs, action):
        """计算与 SFT 的 KL 散度"""
        # 简化
        return 0.1
```
