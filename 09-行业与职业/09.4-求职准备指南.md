## 一、简历准备要点

### 1.1 简历整体原则

| 原则 | 说明 |
|------|------|
| **一页为佳** | 应届/1-3年经验尽量控制在一页；资深可两页 |
| **量化成果** | 用数字描述贡献（如"提升成功率15%"、"训练100万条数据"） |
| **技术导向** | 突出技术栈、项目难点、解决方案 |
| **成果可视化** | 附GitHub链接、项目视频、论文链接 |
| **针对性** | 根据不同岗位调整简历侧重点 |

### 1.4 简历常见错误

| 错误 | 正确做法 |
|------|----------|
| 只列技术名词不写成果 | "使用PPO训练" → "使用PPO在Isaac Lab中训练人形locomotion策略，成功迁移到真实G1机器人" |
| 项目描述过于笼统 | 用STAR法则（情境-任务-行动-结果）描述 |
| 忽略论文/开源 | 论文和开源项目是最大加分项，必须突出 |
| 技能列表过长 | 只列与岗位相关的技能，分"精通/熟练/了解" |
| 没有量化成果 | "优化了训练速度" → "将训练速度提升3倍，从48h降至16h" |
| 格式混乱 | 使用LaTeX或专业模板，保持一致性 |

## 二、作品集与项目展示

### 2.1 为什么需要作品集

具身智能是高度实践导向的领域，一个有说服力的项目展示往往比简历文字更有力量：

- **证明动手能力**：能跑通端到端pipeline比说"了解VLA"更有说服力
- **展示技术深度**：项目中的技术选型和问题解决展示深度
- **区分度高**：大部分候选人只有课程项目，有真实机器人项目的候选人极少

### 2.2 作品集内容建议

#### 必备项目（至少一个）

| 项目类型 | 建议 | 展示形式 |
|----------|------|----------|
| **VLA模型训练** | 基于OpenVLA/π0在自采数据上微调，展示在真实机器人上的操作效果 | 视频+代码+技术博客 |
| **RL Locomotion** | 在Isaac Lab中训练四足/人形locomotion，Sim2Real迁移到真机 | 视频+训练曲线+代码 |
| **模仿学习** | 使用ACT/Diffusion Policy，配合ALOHA/遥操作采集数据，实现操作任务 | 视频+数据采集流程+代码 |
| **仿真环境** | 在Isaac Lab中搭建自定义场景，实现Sim2Real训练pipeline | 仿真视频+真机视频+代码 |

#### 加分项目

| 项目类型 | 建议 |
|----------|------|
| **开源贡献** | 为LeRobot/Isaac Lab等知名项目贡献PR |
| **论文复现** | 复现RT-2/π0/Diffusion Policy等核心论文，开源代码 |
| **竞赛获奖** | 参加机器人竞赛（如RoboCup）或AI竞赛 |
| **系统开发** | 开发完整的遥操作系统或数据处理pipeline |
| **硬件项目** | 自建简单的机械臂或灵巧手控制系统 |

### 2.3 项目展示最佳实践

#### GitHub Profile

```
README.md 中应包含：
1. 一句话自我介绍（方向+核心技能）
2. 核心项目列表（3-5个，带一句话描述和链接）
3. 技术栈列表
4. 联系方式
```

#### 项目 README 模板


#### 视频展示要点

1. **前5秒抓住眼球**：展示最精彩的操作/运动效果
2. **对比展示**：baseline vs yours 的效果对比
3. **技术标注**：在视频中标注关键技术点
4. **真实环境**：优先展示真机效果，仿真效果作为补充
5. **时长控制**：1-3分钟为宜
6. **上传平台**：YouTube / Bilibili，设置公开访问

## 三、面试常见问题

### 3.1 技术面常见问题

#### 3.1.1 基础知识类

| 问题 | 考察点 | 参考答案要点 |
|------|--------|-------------|
| 解释Behavior Cloning的原理和局限 | IL基础 | 监督学习模仿专家；分布偏移问题；DAgger如何解决 |
| DAgger如何解决分布偏移？ | IL进阶 | 交互式收集数据；动态更新策略；on-policy数据分布 |
| PPO和SAC的区别？各适用于什么场景？ | RL基础 | on-policy vs off-policy；样本效率；稳定性；连续动作空间 |
| 解释Sim2Real Gap的原因和解决方案 | Sim2Real | 物理参数不匹配；Domain Randomization；System ID；自适应 |
| 什么是VLA模型？RT-1和RT-2有什么区别？ | VLA基础 | Vision-Language-Action；RT-1纯Transformer；RT-2=VLM+Action |
| Diffusion Policy的原理是什么？ | IL进阶 | 扩散模型生成动作序列；多模态动作分布；噪声调度 |
| ACT（Action Chunking Transformer）的核心思想？ | IL | 动作chunking；Transformer编码；temporal ensemble |
| π0模型和OpenVLA有什么区别？ | VLA进阶 | Flow Matching vs 自回归；连续vs离散动作；跨embodiment |
| 解释MPC的基本原理 | 控制理论 | 在线优化；预测窗口；滚动时域；约束处理 |
| 什么是Whole Body Control？ | 运动控制 | 全身动力学优化；任务优先级；QP求解 |

#### 3.1.2 项目深挖类

| 问题 | 考察点 |
|------|--------|
| 你的项目中最大的技术挑战是什么？如何解决的？ | 问题解决能力 |
| 为什么选择这个算法而不是另一个？ | 技术选型能力 |
| 你的方法和baseline相比提升了多少？原因是什么？ | 实验分析能力 |
| 如果数据量扩大10倍，你的方法会有什么问题？ | 系统性思维 |
| 如何评价你的方法的泛化能力？ | 泛化分析 |
| 在真机上部署时遇到了什么问题？ | 工程能力 |
| 你的代码架构是怎样的？为什么这么设计？ | 工程设计能力 |

#### 3.1.3 编程/算法题

| 类型 | 示例 | 频率 |
|------|------|------|
| **RL算法实现** | 手写PPO/SAC的核心更新逻辑 | 高 |
| **数据处理** | 实现一个数据加载器，处理机器人轨迹数据 | 中 |
| **矩阵运算** | 实现刚体动力学正运动学 | 中 |
| **LeetCode中等** | 动态规划、图搜索等 | 中 |
| **系统设计** | 设计一个遥操作数据采集系统 | 低（资深岗） |

### 3.2 项目面常见问题

#### 项目展示建议

1. **准备5分钟项目介绍**：清晰讲述背景→方法→结果→反思
2. **准备技术细节**：能深入到代码级别的解释
3. **准备失败案例**：诚实讨论什么不work及原因
4. **准备对比分析**：与相关工作的详细对比

#### 常见追问

| 追问 | 应对策略 |
|------|----------|
| "这个结果可复现吗？" | 提供完整的实验设置和随机种子 |
| "如果换一个场景会怎样？" | 讨论方法的局限性，提出改进方向 |
| "你觉得这个方法的本质是什么？" | 从第一性原理解释方法的核心思想 |
| "相关工作有哪些？" | 展示对领域的全面了解 |
| "下一步你会怎么做？" | 展示研究规划能力 |

### 4.2 论文选题策略

#### 好选题的特征

| 特征 | 说明 | 示例 |
|------|------|------|
| **问题重要** | 解决领域核心问题 | VLA模型的泛化问题 |
| **方法新颖** | 有创新的方法论 | 将Flow Matching引入VLA |
| **效果显著** | 实验结果明显优于baseline | 成功率提升20%+ |
| **可复现** | 能开源代码和数据 | 提供完整代码和数据 |
| **时机对** | 赶上领域热点 | 2024年做VLA是好时机 |

#### 推荐选题方向（2025年）

1. **VLA模型改进**：更好的动作表征、更高效的训练、更好的泛化
2. **Sim2Real新方法**：缩小仿真到真实的gap
3. **数据效率**：few-shot操作学习、主动学习
4. **世界模型**：预测性世界模型用于规划和操作
5. **灵巧操作**：高自由度灵巧手的操作学习
6. **多模态融合**：视觉+触觉+语言的融合操作
7. **人形全身控制**：全身协调操作+运动
8. **长程任务**：多步骤复杂任务的规划和执行

### 4.3 论文写作建议

| 阶段 | 建议 |
|------|------|
| **选题** | 多读最新论文，找到gap；与导师/同行讨论 |
| **实验** | 先搭好baseline，确保可复现；多跑对比实验 |
| **写作** | Introduction最重要；用图讲故事；方法部分清晰 |
| **投稿前** | 请3+人review；检查格式；准备supplementary |
| **Rebuttal** | 认真回应每个reviewer；补充实验；保持礼貌 |

### 4.4 论文发表时间规划

以投稿 CoRL（通常3月提交，6月通知）为例：

| 时间 | 任务 |
|------|------|
| T-6月 | 确定选题，文献调研 |
| T-5月 | 搭建实验框架，跑通baseline |
| T-4月 | 实现核心方法，初步实验 |
| T-3月 | 完善实验，消融实验，对比实验 |
| T-2月 | 开始写作，制作图表 |
| T-1月 | 完成初稿，内部review |
| T-2周 | 最终修改，格式检查 |
| T | 提交 |
| T+2月 | Rebuttal |
| T+3月 | 最终结果 |

### 5.4 实习申请策略

1. **广撒网+重点突破**：投10-20家，重点准备3-5家最想去的
2. **优先内推**：通过学长/导师/社区获得内推，通过率高很多
3. **尽早准备**：暑期实习通常2-3月就开始面试，1月就要准备好
4. **面试并行**：不要等一个结果再投下一个，多线并行
5. **展示真实能力**：面试时诚实展示能力，不懂的不要装懂

### 5.5 实习期间如何争取Return Offer

| 策略 | 说明 |
|------|------|
| **快速上手** | 前2周熟悉代码库和工具链 |
| **主动沟通** | 每周与mentor同步进度和计划 |
| **交付成果** | 实习结束时要有可展示的成果 |
| **融入团队** | 参加团队活动，建立关系 |
| **展示潜力** | 展示独立解决问题的能力 |
| **明确意向** | 实习中后期表达return意向 |

## 六、推荐学习的开源项目

### 6.1 面试展示价值最高的项目

以下项目如果能在面试中展示"我读过源码/做过贡献/基于此做了改进"，会极大加分：

#### VLA模型类

| 项目 | 面试价值 | 学习重点 |
|------|----------|----------|
| **OpenVLA** | ★★★★★ | VLA模型架构；数据预处理；微调方法 |
| **openpi (π0)** | ★★★★★ | Flow Matching；跨embodiment训练；推理优化 |
| **RDT-1B** | ★★★★☆ | 双臂VLA；大规模训练；数据效率 |

#### 模仿学习类

| 项目 | 面试价值 | 学习重点 |
|------|----------|----------|
| **LeRobot (HuggingFace)** | ★★★★★ | 完整IL pipeline；ACT/Diffusion Policy；数据管理 |
| **ALOHA / ACT** | ★★★★☆ | 动作chunking；temporal ensemble；遥操作 |
| **Diffusion Policy** | ★★★★☆ | 扩散模型生成动作；噪声调度；条件生成 |

#### RL类

| 项目 | 面试价值 | 学习重点 |
|------|----------|----------|
| **Isaac Lab** | ★★★★★ | GPU加速RL；仿真环境；Sim2Real |

| 项目 | 面试价值 | 学习重点 |
|------|----------|----------|

| **RoboMimic** | ★★★☆☆ | IL benchmark；数据处理 |
| **Genesis** | ★★★☆☆ | 新型仿真平台；Generative仿真 |

### 6.2 推荐学习路径

```
第一步：跑通baseline
├── LeRobot: 跑通ACT在Push任务上的训练
├── Isaac Lab: 跑通PPO训练四足行走
└── OpenVLA: 跑通推理

第二步：自定义任务
├── LeRobot: 在自采数据上训练ACT
├── Isaac Lab: 搭建自定义场景训练
└── Diffusion Policy: 在自定义任务上训练

第三步：真机部署
├── 将训练好的策略部署到真实机械臂
├── Sim2Real迁移测试
└── 采集真实数据微调

第四步：深入改进
├── 阅读源码，理解实现细节
├── 尝试改进方法（如更好的数据增强）
├── 贡献PR到开源项目
└── 基于改进发论文
```

### 6.3 如何在面试中展示开源项目经验

| 展示层次 | 示例 | 效果 |
|----------|------|------|
| **Level 1: 用过** | "我用过OpenVLA做推理" | 基础 |
| **Level 2: 跑通训练** | "我在自采数据上微调了OpenVLA" | 良好 |
| **Level 3: 读过源码** | "我读过OpenVLA的源码，理解了它的tokenizer设计" | 优秀 |
| **Level 4: 做过改进** | "我改进了OpenVLA的动作空间设计，提升了20%成功率" | 极佳 |
| **Level 5: 贡献者** | "我是LeRobot的贡献者，提交了3个PR" | 顶级 |

## 八、求职心态与策略

### 8.1 求职策略

| 策略 | 说明 |
|------|------|
| **T型能力建设** | 在一个方向深入（如VLA），同时了解相关方向（如RL、仿真） |
| **项目驱动** | 用真实项目证明能力，比刷题更有效 |
| **社区参与** | 积极参与开源社区，建立技术声誉 |
| **持续学习** | 具身智能变化快，保持每月读5+篇论文 |
| **人脉积累** | 参加学术活动，建立行业人脉 |

### 8.2 常见心态问题

| 问题 | 建议 |
|------|------|
| **"我没有顶会论文"** | 论文是加分项不是必须项；强项目经验同样有竞争力 |
| **"我不是名校出身"** | 创业公司更看重能力；用项目证明实力 |
| **"我没有真机经验"** | 仿真+开源项目也能展示能力；积极争取真机实习 |
| **"面试总是挂"** | 每次面试都是学习；记录问题，持续改进 |
| **"不知道选哪个offer"** | 综合考虑：技术方向>团队>薪资>公司名气 |

### 8.3 Offer选择框架

| 因素 | 权重建议 | 说明 |
|------|----------|------|
| **技术方向** | 30% | 是否是未来3-5年的核心方向（如VLA） |
| **团队水平** | 25% | 团队技术实力和学习成长空间 |
| **薪资待遇** | 20% | 总包（base+bonus+股权） |
| **公司前景** | 15% | 公司融资情况、商业化进展 |
| **工作环境** | 10% | 加班强度、团队氛围 |

### 8.4 求职时间规划建议

**提前6个月开始准备：**

| 时间 | 任务 |
|------|------|
| **T-6月** | 确定目标方向；开始深入项目 |
| **T-4月** | 论文投稿/开源项目发布；完善简历 |
| **T-3月** | 开始刷题；准备面试；联系内推 |
| **T-2月** | 投递简历；开始面试 |
| **T-1月** | 集中面试；比较offer |
| **T** | 接受offer；入职准备 |
